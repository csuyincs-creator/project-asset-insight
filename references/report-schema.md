路径：

`<output_root>\\<YYYY-MM>\\<YYYY-MM-DD>-<项目名称>-<一句话总结>-项目资产解读.md`

月份目录不存在时自动创建。

## 必需结构

# <项目名称>｜项目资产解读

先放元信息表。

## 01｜30 秒看懂这个项目

100～300 字解释：它是什么、干什么、核心价值、为什么值得知道。

## 02｜它解决什么问题

说明使用背景、原始问题、项目带来的价值。

## 03｜核心能力

提炼真正核心能力，并尽量绑定证据路径。

## 04｜核心架构与实现思路

解释核心调用链、分层与扩展点。

## 05｜最值得借鉴的地方

只保留真正值得学习的设计；不足 3 项不要硬凑。

## 06｜可复用资产

### A｜可直接复用
### B｜适合改造后复用
### C｜只借鉴设计思路

资产建议使用表格：

| 资产 | 类型 | 证据路径 | 作用 | 怎么复用 | 价值 | 复用成本 | 耦合程度 |
|---|---|---|---|---|---|---|---|

## 07｜可以进一步变成我的什么

Skill / Agent / MCP / 工具 / 脚本 / UI / 知识库模块 / 自动化工作流 / 项目脚手架等。

没有明显方向时明确写无。

## 08｜什么时候值得重新打开它

使用“未来问题 → 对应能力/模块”的方式。

## 09｜15 分钟重新理解路线

按顺序列出 5～10 个关键文件或目录，并说明每一步看什么。

## 10｜哪些地方不用继续浪费时间

指出普通样板、自动生成内容、第三方代码、低价值模块等。

## 11｜最终资产结论

包含：

| 维度 | 结论 |
|---|---|
| 项目核心价值 | |
| 最值得借鉴 | |
| 最值得复用 | |
| 是否值得深入研究 | 高 / 中 / 低 |
| 是否值得长期保留 | 是 / 否 / 只保留笔记 |
| 推荐后续动作 | |

最后明确回答：

### 这个项目最值得我记住的是什么？

### 如果以后完全忘记这个项目，只保留一个知识点，应该保留什么？

### 值不值得继续研究？

只能选择：
- 值得深入研究
- 有需要时再研究
- 只需要记住核心思路
- 没必要继续研究

并说明原因。
