# 最终报告结构

文件名：

`<YYYY-MM-DD>-<项目名称>-<一句话总结>-项目资产解读.md`

示例：

`2026-08-20-dsh-oil-creator-数据可视化工具-项目资产解读.md`

报告路径：

`<output_root>/<YYYY-MM>/<YYYY-MM-DD>-<项目名称>-<一句话总结>-项目资产解读.md`

视觉资产路径：

`<screenshot_root>/<YYYY-MM>/<YYYY-MM-DD>-<项目名称>-<一句话总结>-项目资产解读.assets/`

视觉资产目录至少包含 `visual-evidence.json`；存在可视界面且截图成功时至少包含一张截图。

## 必需元信息

最终报告元信息表必须包含：

- 编写来源
- 编写主机
- 文档初次编写时间
- 文档版本号
- 项目名称
- 项目地址
- 项目来源
- 项目网址
- 项目类型
- 本地接触程度
- 核心价值标签
- 截图资产目录
- 截图倍率
- 视觉验证状态

其中截图资产目录、截图倍率来自 TODO-00 的机器级配置；视觉验证状态来自 `visual-evidence.json`。

## 必需结构

# <项目名称>｜项目资产解读

先放元信息表。

## 01｜30 秒看懂这个项目

100～300 字解释：它是什么、干什么、核心价值、为什么值得知道。

## 02｜它解决什么问题

说明使用背景、原始问题、项目带来的价值。

## 03｜核心能力

提炼真正核心能力，并尽量绑定证据路径。

## 04｜核心架构与实现思路

解释核心调用链、分层与扩展点。

## 05｜最值得借鉴的地方

只保留真正值得学习的设计；不足 3 项不要硬凑。

## 06｜可复用资产

### A｜可直接复用
### B｜适合改造后复用
### C｜只借鉴设计思路

资产建议使用表格：

| 资产 | 类型 | 证据路径 | 作用 | 怎么复用 | 价值 | 复用成本 | 耦合程度 |
|---|---|---|---|---|---|---|---|

## 07｜可以进一步变成我的什么

Skill / Agent / MCP / 工具 / 脚本 / UI / 知识库模块 / 自动化工作流 / 项目脚手架等。

没有明显方向时明确写无。

## 08｜什么时候值得重新打开它

使用“未来问题 → 对应能力/模块”的方式。

## 09｜15 分钟重新理解路线

按顺序列出 5～10 个关键文件或目录，并说明每一步看什么。

## 10｜哪些地方不用继续浪费时间

指出普通样板、自动生成内容、第三方代码、低价值模块等。

## 11｜真实运行与视觉验证

这一章是必需章节，不能省略。

至少写明：

- `capture_status`
- `review_status`
- `verification_level`
- 实际运行 / 打开方式
- 截图资产目录
- 使用的 `screenshot_scale`
- 截图列表，或无截图的合规原因
- 机器级校验结果
- Agent 有视觉能力时的视觉复核结论
- 截图与源码分析是否一致

### CAPTURED

若 `capture_status=CAPTURED`：

- 至少引用一张真实截图
- 推荐主图为 `01-overview.png`
- Markdown 中必须出现截图文件名
- Agent 有视觉能力时必须补充截图语义检查

截图根目录与报告根目录相同时，优先使用相对链接。

若用户把 `screenshot_root` 指向其他目录或其他磁盘，报告中至少要写出完整截图资产目录，并使用当前 Markdown / Obsidian 环境可访问的真实链接形式；不得伪造相对路径。

### NO_VISUAL_SURFACE

必须写清：

- 为什么确认整个项目没有可视界面
- 检查过哪些入口
- 证据是什么

### CAPTURE_BLOCKED

必须写清：

- 存在哪个可视入口
- 实际尝试了什么
- 真实错误是什么
- 检查了哪些 fallback
- 为什么判定当前环境客观无法完成截图

## 12｜最终资产结论

包含：

| 维度 | 结论 |
|---|---|
| 项目核心价值 | |
| 最值得借鉴 | |
| 最值得复用 | |
| 是否值得深入研究 | 高 / 中 / 低 |
| 是否值得长期保留 | 是 / 否 / 只保留笔记 |
| 推荐后续动作 | |

最后明确回答：

### 这个项目最值得我记住的是什么？

### 如果以后完全忘记这个项目，只保留一个知识点，应该保留什么？

### 值不值得继续研究？

只能选择：
- 值得深入研究
- 有需要时再研究
- 只需要记住核心思路
- 没必要继续研究

并说明原因。
