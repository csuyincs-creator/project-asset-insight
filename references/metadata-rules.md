# 元信息动态填写规则

最终报告必须包含元信息表，但 Skill 只规定“字段与获取方式”，不规定具体值。

| 元信息项 | 获取规则 |
|---|---|
| 编写来源 | 根据当前实际执行 Agent / Skill 环境填写；无法确认则填 `无法确认` |
| 编写主机 | 读取当前操作系统 hostname |
| 文档初次编写时间 | 当前系统实际时间 |
| 文档版本号 | 新建默认 `V1.0.0` |
| 项目名称 | 结合 README、manifest、目录名、Git remote 综合识别 |
| 项目地址 | 当前项目实际绝对路径 |
| 项目来源 | 根据 Git remote、README、manifest、文档确认 |
| 项目网址 | 优先官方 repo、homepage、README 官方链接；无法确认则填 `无法确认` |
| 项目类型 | 根据项目实际核心用途归纳，不限制固定枚举 |
| 本地接触程度 | 根据当前项目实际证据判断；证据不足填 `无法确认` |
| 核心价值标签 | 完成 TODO-03～07 后提炼 3～8 个关键词 |

## 禁止把规则文本写入最终报告

以下内容属于提示词，不是答案，严禁原样出现在最终元信息值中：

- 自动识别
- 自动生成
- GitHub / 官网 / 其他
- 爬虫 / Agent / UI / 知识库 / Prompt / 自动化等
- 仅收藏 / 已阅读 / 深入研究 / 已使用
- 多平台采集、评论分析、浏览器自动化等
- 待填写 / TBD / TODO / xxx

## 本地接触程度

仅作为元信息一行，不展开运行审计。

可根据实际证据使用类似表述：
- 仅发现本地源码
- 存在研究痕迹
- 存在二次开发痕迹
- 存在实际使用痕迹
- 无法确认

不要为了填满字段而猜测。
