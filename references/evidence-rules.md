# 证据规则

## 结论类型

最终报告中的重要判断应区分：

- 文档明确说明
- 源码确认
- 配置确认
- Git/项目元数据确认
- Agent 推断
- 无法确认

## 必须绑定证据路径的内容

以下内容尽量绑定实际文件或目录：
- 核心能力
- 核心架构
- 可复用资产
- 关键实现思路

建议格式：

**对应证据**
- `path/to/file`
- `path/to/module/`

## 无证据时

若只能合理推断，明确写“推断”。

若无法确认，写“无法确认”。

禁止编造：
- 作者意图
- 商业模式
- 实际用户量
- 项目效果
- 用户当时为什么 Clone
- 用户是否真正使用过

对于“为什么可能值得保存”，只能写“可能的关注点”。
